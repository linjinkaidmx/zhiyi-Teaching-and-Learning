# 知一 · 服务器部署说明

> **为什么必须部署后端**：AI 的 API Key 绝不能写在前端代码里（任何人查看源码都能拿到）。
> 必须在服务端调用模型，因此需要一个公网可访问的后端服务。

## 架构：前后端一体化（同源）

本项目采用**单进程同源部署**——一个 uvicorn 进程同时提供前端页面和 API：

```
浏览器 ──→ http://服务器IP:3300
              │
              ├─ GET  /            → 前端页面（backend/static/）
              ├─ GET  /api/health  → 健康检查
              └─ POST /api/diagnose→ AI 诊断（内部调用火山方舟）
```

**这样做的三大好处：**

1. **彻底规避混合内容问题**：页面和接口同源同协议，浏览器不会拦截
2. **零 Nginx 配置**：不需要买域名、不需要申请 HTTPS 证书
3. **一次构建处处可用**：前端请求走相对路径 `/api/...`，换服务器不用重新打包

> 前端构建时把 `VITE_API_BASE` 设为空字符串（见下方「重新打包前端」），
> 请求即走相对路径。代码里用的是 `??` 而非 `||`，空串不会被默认值覆盖。

## 快速部署（推荐：3 条命令）

### 第 1 步：上传部署包

在本机终端（Git Bash / PowerShell / 终端）执行：

```bash
scp "C:/Users/ASUS/LearnBuddy/2026-09-16-22-37-51/zhiyi-release.zip" root@193.112.28.51:/opt/
```

输入服务器密码后即开始上传（约 425 KB，几秒完成）。

### 第 2 步：登录服务器并解压

```bash
ssh root@193.112.28.51

# 登录后在服务器上执行（二选一）
cd /opt && unzip zhiyi-release.zip        # 有 unzip 时
cd /opt && python3 -m zipfile -e zhiyi-release.zip /opt/   # 没有 unzip 时用这个
```

解压后确认目录结构：

```bash
ls /opt/zhiyi/backend/
# 应能看到：main.py  schemas.py  service.py  requirements.txt  .env  static/
```

### 第 3 步：一键部署

```bash
bash /opt/zhiyi/deploy/install.sh 3300
```

脚本会自动完成：安装系统依赖 → 建虚拟环境 → 装 Python 包 → 配 systemd 开机自启 → 健康检查。

看到 `✓ 部署成功！` 即完成，访问 **`http://193.112.28.51:3300`**。

> 默认端口 3300，想换端口把参数改掉即可：`bash /opt/zhiyi/deploy/install.sh 8080`

## ⚠️ 打不开页面怎么办

**99% 的原因是端口没放行。** 去云厂商控制台找到这台服务器：

- 腾讯云：控制台 → 实例 → **安全组** → 添加入站规则 `TCP:3300  来源 0.0.0.0/0`
- 阿里云：**安全组规则** → 入方向 → 允许 `3300`
- 华为云：**安全组** → 入方向规则 → 放行 `3300`

若还不行，检查系统自身防火墙：

```bash
# Ubuntu / Debian
ufw allow 3300 && ufw reload

# CentOS / Rocky
firewall-cmd --permanent --add-port=3300/tcp && firewall-cmd --reload
```

快速判断依据：
- **能 SSH 进去但网页打不开** → 端口/安全组问题（连接超时）
- **连接被拒绝（refused）** → 服务没起来，看日志 `journalctl -u zhiyi -n 50`

## 常用运维命令

```bash
systemctl status zhiyi              # 查看运行状态
systemctl restart zhiyi             # 重启服务
systemctl stop zhiyi                # 停止服务
journalctl -u zhiyi -f              # 实时看日志（Ctrl+C 退出）
curl http://127.0.0.1:3300/api/health   # 本机健康检查
```

服务已配置为**开机自动启动**，服务器重启后无需手动干预。

## 重新打包前端（仅当前端源码有改动时）

```bash
cd zhiyi/frontend

# 关键：VITE_API_BASE 设为空串，让请求走同源相对路径
VITE_API_BASE= npm run build -- --outDir ../backend/static --emptyOutDir
```

然后重新执行「上传 → 解压 → install.sh」即可覆盖更新。

> 若只需要更新静态页面，可以只替换 `backend/static/` 目录的内容，
> 再 `systemctl restart zhiyi` 即可，不必重跑完整安装脚本。

## 可选方案：Docker Compose

服务器上已安装 Docker 时，可用容器方式部署（同样监听 3300）：

```bash
cd /opt/zhiyi/backend
cp .env.example .env && vi .env      # 填入火山方舟 Key
docker compose up -d --build
docker logs -f zhiyi-backend
```

`docker-compose.yml` 的端口映射为 `3300:8000`。

## 常见问题排查

| 现象 | 原因与处理 |
|---|---|
| 网页能开，诊断一直转圈 | `journalctl -u zhiyi -f` 看是否报 Key 错误；确认 `.env` 中 `ARK_API_KEY` 正确且有余额 |
| 诊断报「未配置 ARK_API_KEY」 | 确认 `.env` 位于 `backend/` 目录，变量名必须是 `ARK_API_KEY` |
| 单题耗时超过 60 秒 | 火山方舟偶发慢，属正常；可调大模型超时或换用 `doubao-seed-2-1-turbo` 提速 |
| `pip install` 很慢或超时 | 脚本已用清华源；仍慢可在服务器上手动换源 |
| 端口通但页面 404 | 检查 `backend/static/index.html` 是否存在 |
| 服务启动后立即退出 | `journalctl -u zhiyi -n 50` 看具体 traceback |

## 生产环境加固建议（可选，工程完整性加分）

- 给 source 加 HTTPS：`certbot` 申请免费证书 + Nginx 反代，届时把 `VITE_API_BASE` 留空仍能同源工作
- 把 `main.py` 中 `allow_origins=["*"]` 收紧为实际域名白名单
- 定期轮换火山方舟 API Key，`.env` 切勿提交进 Git 仓库
- 加简单的请求频率限制，防止 Key 被盗刷
