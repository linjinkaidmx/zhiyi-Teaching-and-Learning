# 如何邀请别人参与你的 GitHub 项目

> 你的仓库：`github.com/linjinkaidmx/zhiyi-Teaching-and-Learning`（公开）

---

## 先分清两种方式（很多人会混）

| 方式 | 对方权限 | 适合谁 | 你需要做什么 |
|---|---|---|---|
| **协作者（Collaborator）** ✅ 推荐 | **可直接 push**，等于共同拥有者 | 你的队友（王雨茜、金铭彬） | 在设置里邀请，对方接受 |
| Fork + Pull Request | 只能提修改请求，**不能直接改** | 陌生人、开源贡献者 | 什么都不用做，对方自己 fork |

**给队友就给 Collaborator**，Fork 那套是给陌生人的，队友用会很别扭（每次都要你审核合并）。

---

## 第一步：你发出邀请（约 1 分钟）

1. 打开仓库页面：`https://github.com/linjinkaidmx/zhiyi-Teaching-and-Learning`
2. 点顶部 **Settings**（设置）
   - 如果没有 Settings 标签，说明你不是这个仓库的 owner（那就没法邀请）
3. 左侧菜单找到 **Collaborators**（新版叫 **Collaborators and teams**）
4. 点绿色按钮 **Add people**
5. 输入对方的 **GitHub 用户名**（或注册邮箱、或姓名），从下拉里选中正确的人
6. 点 **Add <对方名字> to this repository**
7. 会让你确认一次密码（或 2FA）

> 对方此时会收到**邀请邮件**，仓库设置页里也会显示为 **Pending invite**（待接受）。
> **邀请不是立刻生效**——必须对方接受后才拥有权限。

---

## 第二步：对方接受邀请（3 种方式，任选一种）

**方式 A：点邮件里的链接（最直接）**
邮件标题类似「*[GitHub] @linjinkaidmx has invited you to collaborate*」→ 点里面的 **View invitation** → 在打开的页面点 **Accept invitation**。

**方式 B：从网页接受（没收到邮件时用这个）**
让对方登录 GitHub 后直接打开：
```
https://github.com/linjinkaidmx/zhiyi-Teaching-and-Learning/invitations
```
页面上会列出待接受的邀请 → 点 **Accept**。

**方式 C：从通知中心**
GitHub 右上角铃铛（Notifications）里会有邀请通知 → 点进去接受。

> 如果对方说"没收到邮件"：让他先看**垃圾邮件箱**，或直接用方式 B 的链接；再不行就检查你输入的**用户名/邮箱是否拼错**，可以在 Collaborators 页面删掉重发。

---

## 第三步：对方开始协作（接受之后）

接受后，对方可以用**自己的 GitHub 账号**正常推送：

```bash
# 第一次：把仓库拉到本地
git clone https://github.com/linjinkaidmx/zhiyi-Teaching-and-Learning.git
cd zhiyi-Teaching-and-Learning

# 之后每次协作前先同步，避免冲突
git pull

# 改代码…
git add -A
git commit -m "feat: 说明这次改了什么"
git push
```

**几条减少冲突的约定**（三人协作建议）：

1. **每次动手前先 `git pull`** —— 最常见的问题就是 "push 被拒，因为远端更新了"
2. 如果 push 被拒：先 `git pull --rebase`（把你的提交挪到最新之上），再 `git push`
3. **别同时改同一个文件** —— 比如前端由王雨茜改，后端由你改，边界清晰
4. 提交信息统一格式（本项目已有习惯）：`feat:` 新功能 / `fix:` 修 bug / `docs:` 文档 / `chore:` 杂项

## 需要注意的几件事

**1. 给写权限意味着什么**
Collaborator 可以**直接改、甚至删**仓库里的任何东西，包括推送、删除分支、改设置外的内容。这是协作的正常代价，但：

- **不要共用账号或 Token**：每人用**自己的** GitHub 账号，这样提交记录里能看到是谁做的（对参赛材料也重要）
- 项目做完（或不再协作）后，可以在 **Settings → Collaborators** 里点 **Remove** 移除权限

**2. 队友推送用的凭据**
- 队友 push 时会要求登录，**用他自己的账号**即可（不需要你的密码或 Token）
- 如果队友遇到 `Authentication failed`：GitHub 不能用密码推送，需要生成一个**自己的** Personal Access Token（头像 → Settings → Developer settings → Personal access tokens → Tokens (classic) → 勾 `repo`）

**3. 只想让队友"出现在项目里"、但不给写权限？**
也可以——只要他们自己 fork 或用 PR 提交过一次，提交记录里就会留下名字；参赛材料里的团队信息也已经在 PPT / 视频 / README 里写明了，**不需要 GitHub 权限**。权限只影响"能不能直接推代码"。

**4. 关于评委**
评委通常**不会登录 GitHub**，所以：
- 仓库保持**公开**（现在就是公开的）
- 不需要给评委任何权限
- 提交记录里有三人的贡献痕迹，比"只有一个人"更好看

---

## 快速检查：邀请是否生效

| 状态 | 在哪看 |
|---|---|
| 已发出、等对方接受 | Settings → Collaborators 显示 **Pending invite** |
| 已接受 | 该页面显示对方的**头像与用户名**，且不再带 pending 标记 |
| 已验证权限 | 对方 `git push` 一次成功即可确认 |

---

## 一句话总结

**你**：Settings → Collaborators → Add people → 输入对方 GitHub 用户名 → 发送
**对方**：点邮件里的 Accept（或打开 `你的仓库地址/invitations` 点 Accept）
**之后**：对方用自己的账号 clone → 改 → push；每次动手前先 `git pull`
