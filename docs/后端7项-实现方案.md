## ② 讲解流式 ✅ 已完成（批次3）

**核心难点**：讲解结果是 JSON，直接流式吐出来用户看到的是 `{"answer":"` 这种碎片 → 必须在服务端做**增量字段解析**。

**落地结果**：
- `service.scan_json_strings(text)`：扫描（允许被截断的）JSON，收集所有**字符串值**的 `(path, raw, closed)`；路径形如 `answer` / `steps[0].detail` / `knowledge_points[2]`
- `service._decode_partial(raw)`：解码（可能截断的）JSON 字符串；**结尾半个转义序列（单独的 `\` 或 `\u12`）会挂起**，不会把 `\n` 显示成 `\` + `n`
- `service._diff_field_events(buffer, emitted, done)`：对比累积文本 → 只产出**新增文本**的增量事件（同一 buffer 重扫不重复发）
- `service.explain_stream(question, attempt, depth)`：生成器；事件协议 `{field,delta}` / `{field_done}` / `{done,result}` / `{error}`
- 端点 `POST /api/explain/stream`（SSE）；**首 token 之前失败 → 自动降级为非流式完整调用**并标 `fallback=True`；已出字后失败 → 报 error（不发 done）
- 前端：`api.explainStream`；`flowStore.explainOne()` 边收边写 `item.stream`（`{fields, order, done, active}`）；`ExplainPage` 在 loading 阶段渲染「逐字段面板」（纯文本 + 光标），`done` 后切回结构化渲染（MathText/MarkdownText）
- **渲染分工沿用既有规则**：流式阶段纯文本，完成后才渲染公式（避免每个 delta 重排 KaTeX）

**测试**：`_test_partial_json.py` **37 项**（含分片拼接 == 最终解析结果、转义、半个转义挂起、路径正确性、空字段不发 delta）+ `_test_explain_stream.py` **24 项**（端点、深度、降级、中途失败）



**难点**：`/api/explain` 返回的是**结构化 JSON**（`answer` / `steps[].detail` / `knowledge_review` …）。直接流式吐 JSON，用户看到的是 `{"answer":"…` 这种碎片 → 必须在服务端做**增量字段解析**。

**做法**
1. 服务端逐片接收模型输出，维护一个 buffer；用一个轻量**增量 JSON 字段提取器**（`_partial_fields`）：解析出「已完整的字符串字段」与「当前正在写入的字段」，只把**新增文本**作为 delta 发出
2. 事件协议（前端渲染所需信息齐全）

```
data: {"field":"answer","delta":"x = 1"}          -- 答案逐字
data: {"field":"steps[0].title","delta":"化简"}    -- 步骤标题
data: {"field":"steps[0].detail","delta":"由…"}    -- 步骤正文
data: {"field":"__field_done","value":"steps[0]"}  -- 该字段结束（前端可切 MathText 渲染）
data: {"done":true,"result":{...完整结果...}}        -- 结束后给完整对象（前端做最终校验/替换）
data: {"error":"..."}
```
3. **降级**：首 token 之前失败 → 自动改为非流式 `explain_question()` 完整调用（用户仍能拿到讲解）；已出字后失败 → 报错（与现有 follow-up 策略一致）
4. `_repair_json` / `_restore_control_chars` 已有的 JSON 修复能力继续用于最终 `result`

**解释：为什么不是"改成纯文本输出"** —— 那会丢掉结构化渲染（步骤卡片、易错点折叠、知识点标签），得不偿失。

**前端改动**：`ExplainPage` 的 `api.explain` → `api.streamPost('/api/explain/stream')`，按 field 累积到同一个 result 对象；渲染分工沿用既有规则（**流式阶段纯文本，`__field_done` 后切 `MathText`/`MarkdownText`**）
**验收**：`_test_explain_stream.py`（MOCK 下校验事件序列、拼接结果 == 非流式结果、中途错误处理）

## 跨项统一约定

1. **MOCK=1 全离线可测**：所有新增端点都有内置桩，测试脚本不依赖网络与 Key
2. **缓存表统一模式**：`hash → result`，响应带 `cached: bool`，避免重复计费
3. **调用位复用**：不新增模型配置；`deep` 类走 EXPLAIN_SLOT，`快` 类走 JUDGE_SLOT；识别永远留方舟（DeepSeek 无视觉）
4. **超时/降级**：沿用 `EXPLAIN_FALLBACK=1` 的"超时降级 turbo 不开思考重试"策略

| # | 现象 | 根因 | 修法 |

| 1 | 对话详情页永远空态（左侧列表却显示"2 条"） | 会话 id 是 `nextId()` 的数字，而路由参数 `/chat/:id` 是**字符串** → `getChat()` 严格 `===` 永远不命中 | `chatStore` 全部按 id 做**字符串归一**；补 5 项回归 |
