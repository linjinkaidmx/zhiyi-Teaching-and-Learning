## 2. 严重 Bug 清单（核心搜题问题置顶）

> ✅ **S1、S2 已于 2026-09-20 修复上线**，详情见文末「修复记录」

### S1. 模糊图片：识别耗时 178 秒，且把"无法识别"当成题目继续讲解
- **问题位置**：拍题页（/capture）→ 上传模糊图 → 开始识别 → 后端 `/api/extract`
- **问题现象**：上传重度高斯模糊的题目图后点识别，**等了 178 秒（近 3 分钟）**才返回；且返回的"题干"是模型的自述文本——「图像过于模糊，无法识别其中的文字内容。」。这个文本被当作识别**成功**（`ok=true`）返回，前端会继续进入讲解流程，最终生成一份「讲解"图像过于模糊"这句话」的荒谬结果。
- **复现概率**：必现（模糊图）
- **问题影响**：用户干等 3 分钟；拿到的是**答非所问的讲解**，直接摧毁对识别功能的信任。属核心搜题链路错误。
- **修复建议**：
  1. 后端识别到"无有效题目内容"时返回 `ok=false` + 友好错误（如"这张图太模糊，没识别到题目，请重拍或换一张更清晰的图"），**绝不把模型的自述/道歉语当题干**；
  2. 前端对"题干疑似模型自述"做兜底拦截（如命中"图像过于模糊/无法识别"关键词则不进入讲解）；
  3. 对低质量图缩短超时，别打满 120s。

### S2. 空白/无内容图片：识别 180 秒超时
- **问题位置**：拍题页（/capture）→ 上传空白图 → 开始识别 → `/api/extract`
- **问题现象**：上传纯白空白图后点识别，**180 秒后 TimeoutError**，前端只能提示"识别超时了，请重试一次；若仍失败，换一张更清晰、背景更简单的图"。
- **复现概率**：必现（空白/近纯色图）
- **问题影响**：用户干等 3 分钟才得到"超时"，体验等同卡死；学生拍黑板/白纸误触时尤其常见。
- **修复建议**：空白/近纯色图应在**前端或后端做快速预检**（如像素方差、尺寸、近乎无边缘），秒回"未识别到题目，请重新拍摄"，不要进入模型调用打满超时。

## 3. 一般 Bug 清单

### G1. 正常清晰图：识别结果选项缺失
- **问题位置**：识别内容完整性（选择题）
- **问题现象**：原题含 4 个选项（A) 0 B) 1 C) -1 D) does not exist），识别结果只到「…A) 0  B) 1」，**C、D 两个选项丢失**。
- **复现概率**：偶现（与选项排版/换行相关）
- **问题影响**：选择题选项不全会导致后续讲解、批改、变式题都基于残缺题干，匹配与解析质量下降。
- **修复建议**：识别提示词强调"完整输出全部选项、逐项不要截断"；对识别出的选择题做选项数量校验，不完整时重试或降级为"题目不完整，请重拍"。

### G2. 倒置图片：识别正确但耗时 35 秒（正常 6 秒，约 6 倍）
- **问题位置**：倒置/旋转图识别的性能
- **问题现象**：180° 倒置的题目图，模型能自动纠偏并识别正确，但耗时 35.3 秒（同图正常方向 6.2 秒）。
- **复现概率**：必现（倒置图）
- **问题影响**：不失效但明显偏慢；用户拍照偶发倒置时会感觉"卡"。
- **修复建议**：上传前做方向检测并自动旋正（前端 EXIF/图像方向 + 简单边缘方向启发式），减少模型纠偏负担。

## 4. 轻微问题 / 优化点

### M1. 拖拽 / 粘贴非图片文件时静默无反馈
- **位置**：拍题页拖拽区、粘贴通道
- **现象**：拖入一个 .txt 或粘贴非图片内容，**没有任何提示**（`onDrop`/`onPaste` 对非 image 直接跳过）。而「相册选择」路径有 toast「请选择图片文件」。三者行为不一致。
- **修复建议**：非图片拖入/粘贴时统一提示「请拖入图片文件」。

### M2. 上传无大小/尺寸限制、无压缩
- **位置**：拍题页上传链路
- **现象**：图片不做压缩直接 `readAsDataURL`（base64 膨胀约 33%），无大小上限。手机高清照（4MB+）在弱网下上传慢、占用内存高，可能放大超时概率。
- **修复建议**：前端用 canvas 压缩（最长边降到 1600px、JPEG 质量 0.85），并设上限（如 >10MB 拒绝并提示）。

### M3. 识别超时与失败两套文案措辞不统一
- **位置**：识别错误提示
- **现象**：超时是"识别超时了，请重试一次…"、其它失败是"识别失败：xxx"，风格不一致；建议统一为一句可执行的用户话术。

## 5. 整体测试总结

**问题概况**：核心搜题链路的"正常路径"可用且质量尚可（清晰图 6 秒识别正确、倒置/残缺/反光图都能纠偏识别），但**异常图片是当前最脆弱的一环**——模糊图"识别失败被当成成功"（S1）和空白图"干等 3 分钟超时"（S2）都是必现、且直接伤害核心体验。整体未发现"正常清晰图搜题完全失效""解析空白""页面崩溃"这类灾难级问题。

**搜题核心风险点（按优先级）**：
1. **异常图片的失败语义错误**（S1、S2）—— 识别失败必须明确返回失败，且要快。这是本轮最高优先级。
2. **识别内容完整性**（G1 选项缺失）—— 直接影响选择题的匹配与解析质量。
3. **异常图性能**（G2 倒置慢）—— 建议前置旋正。

**已验正常的维度**（自动化覆盖，供对照，避免误报）：
- 全站 17 路由渲染、零控制台错误；3 档宽度（390/768/1440）× 20 路由零横向溢出；双主题正文对比度
- 文字搜题（输入后按钮可用 → 跳转讲解）、四上传通道入口、照片查看器（缩放/拖动/Esc）
- 登录/注册/改昵称/注销/云同步（错题+统计+课程+记录五表）—— 后端 46 项 + 线上 16 项
- 对话流式、讲解流式逐字段、变式题（1.7s/道）、学情建议真实链路
- 断网刷新不白屏（浏览器兜底页）；拖入非图片之外的交互无未捕获异常

**优先修复排序**：S1 → S2 → G1 → G2 → M1 → M2 → M3。

## 修复记录（S1/S2 + G1/M1/M2，2026-09-20）

**根因**（都在后端，前端 `ok:false` 处理本就正确）：
- S1：`/api/extract` 对「模型返回的自述文本（"图像过于模糊，无法识别"）」没有判定，直接 `ok=true` 返回，前端继续进讲解
- S2：空白/近纯色图无预检，直接进视觉模型打满 120s 超时

**修法**（`service.py` + `main.py`）：
1. 新增 `NoQuestionError` + `_looks_like_no_question(text)`（空 / 过短 ≤3 字 / 命中自述·道歉句式正则 → 判无题目），识别转写统一过滤
2. 新增 `_image_is_blank_or_invalid`（灰度标准差 < 14 = 近纯色；PIL 打不开 = 无效图）与 `_image_is_too_blurry`（FIND_EDGES 边缘能量 < 8 = 重度模糊），在调用模型前快速失败
3. 端点把 `NoQuestionError` 映射为友好提示，不再记成系统错误

**回归验证（真实模型，9 张异常图）**：

| 图 | 修复前 | 修复后 |
|---|---|---|
| 空白图 | 180s 超时 | **0.1s** 友好提示 |
| 模糊图 | 178s + 把"无法识别"当题干 | **0.1s** 友好提示、干净失败 |
| 正常/倒置/残缺/反光 | 识别正确 | 不变（仍正确） |

**新增回归**：`_test_extract_guard.py`（22 项，覆盖自述句式/空白/模糊/无效图/不误判）；后端 13 套全绿。

## 修复记录（第三轮：G2，2026-09-20）

- **G2 倒置/旋转图慢**：根因是手机照片的 **EXIF 方向元数据**没被应用 —— 之前 `<img>` + canvas 画图会**丢掉方向**，视觉模型拿到没转正的像素，要自己脑补旋转（实测 35~79s）。
- 修法：`CapturePage` 改用 `createImageBitmap(file, { imageOrientation: 'from-image' })`，让浏览器**自动转正**后再缩放；不支持时降级 `<img>`（方向可能丢但至少不报错）。
- 验证：浏览器 API 实测确认方向被应用（200×100 + Orientation=6 → 100×200）；构建 + 冒烟 + 前端 10 套全绿。
- 边界说明：这只修"带 EXIF 方向元数据的照片"（手机拍照最常见）；**像素本身真的倒置、又没有 EXIF 的图**不在其列（属罕见情况）。
- 已部署（前端 dist49）。

**全部修复完毕**：S1/S2/G1/G2/M1/M2/M3 已全部修复并上线。
