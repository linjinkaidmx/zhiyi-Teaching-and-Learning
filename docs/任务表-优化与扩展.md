## ✅ 优化 ② 首屏加载提速（已完成 dist145）

**结果**：首页可用 **3990ms → 1618ms（-59%）**；传输 **902KB → 506KB（-44%）**；DOMContentLoaded 3736ms → 612ms。
   做法： 按需注入 chart/codemirror（index.html 去掉 4 个同步 script），hljs 因被高频文本组件使用而保留。
   复测脚本：（支持标签参数）；功能验证  5/5。

**原目标**：首次打开可用时间从 3s+ 降到 1.5s 内。

**技术现状（已核对）**
- 路由**已分包**（产物里 HomePage/MinePage/ClassDetailPage… 都是独立 chunk，MathText 290KB 也单独成 chunk）
- **真正的瓶颈在 `index.html`**：`chart.umd.js`、`highlight.min.js`、`codemirror*.js`（4 个文件）是**同步 `<script>`**，约 700KB，阻塞首屏
- 服务器是 FastAPI StaticFiles（需确认是否开了 gzip/brotli）

**子任务**
1. 测基线：CDP 记录首屏资源数、传输总量、`DOMContentLoaded`、首页可用时刻（脚本化，可复跑）
2. 把 codemirror（4 个文件）改为**进入代码编辑器/在线判题页时才动态注入**
3. 把 `chart.umd.js` 改为**数据页/考试结果页按需加载**
4. `highlight.min.js` 与 hljs 样式改为**遇到代码块时按需加载**
5. 确认服务端 gzip/brotli 已开（FastAPI `GZipMiddleware`），静态资源长缓存头
6. 复测同一套指标，出对比数据

**验收**：首屏传输量下降 ≥50%，首次可用时间 <1.5s；进入代码/图表页面时有多余依赖的加载提示（不能白屏）

**风险**：按需加载会让"首次进入代码编辑器"多 1~2s → 加 loading 态即可

## ✅ 优化 ③ 班级群聊实时化（已完成 dist147）

**目标**：老师布置作业/同学发言后，同班其他人无需手动刷新即可看到。

**技术方案**：SSE（复用现有 `api.streamPost` 的 fetch 手解帧通道，后端 `StreamingResponse` 已在这一套里跑通）

**子任务**
1. 后端新增增量消息接口：`/api/class/messages/stream`（入参 token + class_id + since_id），async 生成器每 2s 查一次新消息，有则推、无则心跳
2. 前端 `ClassDetailPage` 进入群聊 tab 建立连接，收到新消息追加到列表并提示"有新消息"
3. 生命周期：切走 tab / 离开页面关闭连接；断线自动重连（指数退避，最多 3 次）
4. 自己的消息不重复插入（按消息 id 去重）
5. 群聊列表底部"刷新"按钮保留（兜底）

**验收**：两个浏览器（老师+学生）同时开同一班级群聊，一方发言，另一方 2~3s 内自动出现；断网重连后消息补齐

**风险**：SSE 长连接会占用服务端连接（单进程 uvicorn）→ 先按"每班最多 3 条连接"思路做，并在实测中观察连接数
