# 参赛材料 · 技术亮点（PPT / Demo 视频内容来源）

> 用途：这 8 条是**"技术创新性 30%"**的弹药。每条都按同一个结构写：
> **一句话亮点**（可直接放 PPT 标题与视频口播）→ 背景问题 → 做法 → **实测数据** → 为什么难
> 数据全部来自开发过程中的真实测量，不是估算。

---

## 亮点 1 · 批改架构用 A/B 实测选型，而不是凭直觉

**一句话**：把"合并调用"的新方案拿真实数据测了一遍，发现它更慢更脆，于是**主动否决**了自己想出的优化。

- **背景**：原方案两次调用（视觉转录 + 文本判分）。设想中的"V2"把两步合并成一次视觉调用，直觉上更省调用、更快。
- **做法**：3 个样本（1 张线上真实手写作业图 + 2 张构造的边界样本：跳步、涂改），两版各跑 2 次，共 **20 次真实模型调用**，比分数、转录质量、耗时、失败率。
- **实测数据**：

| 指标 | V1（现状，两段式） | V2（合并为一次调用） |
|---|---|---|
| 分数 | 95 / 95 | 95 |
| 转录 | 131 字（两次**逐字一致**） | 131 字（**与 V1 逐字相同**） |
| 耗时（同图） | **7.5s / 8.2s** | **277.5s** |

- **结论**：V2 质量零增量、耗时高一个量级，还多一个"一次失败整份重来"的风险 → **不采用**。
- **转身做了更值的事**：把优化点从"省一次调用"换成"零成本增强"——在转录提示词里要求标注纸面信息（见亮点 6）。
- **为什么难 / 体现什么**：面对"看起来更先进"的方案，用**可复现的实测**做取舍，而不是拿架构漂亮当理由。评分表里"技术创新性"要的是这种判断。

## 亮点 2 · 题库跨写法命中：从 0 次命中到 1.000

**一句话**：盘出一个"只进不出"的题库——273 条题目、**命中次数全部为 0**，把命中率做到接近 100%。

- **背景**：题库设计是"AI 讲解完自动回填、下次同题直接复用答案"，但线上 273 条记录的命中计数**全是 0**。
- **诊断**：命中判定要求文本相似度 ≥ **0.96**，等于要求"几乎逐字相同"；而拍照识别的空格、标点、题号、LaTeX 写法差异，会让**同一道题**掉到 0.55~0.86。
- **做法**：三层改造
  1. **归一化增强**：去标点 → 剥开头题号 → LaTeX 命令等价化 → **Unicode 数学符号映射**（`√`↔`\sqrt`、`x²`↔`x^2`、`∫`↔`int`）→ 去花括号
  2. **阈值下调** 0.96 → **0.90**
  3. **数字指纹剥题号**（"21. 已知…"里的 21 不是题目数值，不再导致误判为不同题）
- **实测数据**（离线 12/12 + 线上真实库复验）：

| 同一道题的写法 | 优化前 | 优化后 |
|---|---|---|
| 带题号 + 无空格 + 半角标点 | 0.545 ✗ | **1.000 ✓** |
| **LaTeX 写法**（`\frac` / `\sqrt`） | 0.444 ✗ | **0.947 ✓** |
| 加「第 3 题」前缀 | — | **1.000 ✓** |
| 不同题（差一个数值） | — | **正确拦截 ✓** |

- **为什么难**：既要"同题不同写法能命中"，又要"差一个数字不能误命中"——两个目标互相冲突，靠**归一化 + 数字指纹双重校验**才拆开。副产品：留下了"相似候选"接口，将来可做"是不是这道题"的确认交互。

## 亮点 3 · 批改任务化：老师关掉页面，服务端继续批

**一句话**：把"前端循环调接口"改成**服务端批改任务**，老师点完就能去干别的，回来再看进度。

- **背景**：原来批改是前端逐份循环调用，**老师一关页面批改就断了**，几十份作业必须守着。
- **做法**：服务端内存任务表（`task_id` 为主键 + 作业索引）+ 线程池并发 3；接口拆成"启动任务"与"查进度"；前端 2 秒轮询，进度含**已用时长与剩余预估**（按已完成份数的平均耗时推算）；重复点击自动复用进行中的任务；单份失败不中断整批。
- **实测数据**：端到端断言 **12/12** 通过——权限拦截 / 空态 / 学生重交造待批 / 启动 / 重复启动复用同一任务 / 进度推进到完成 / 完成后仍可查 / 结果落库。
- **踩坑（值得写进 PPT 的"工程细节"）**：任务表原按 `homework_id` 存、后台线程按 `task_id` 查，导致**进度恒为 0**（批改其实在跑、结果也落库了）。是从"结果已落库"这条断言通过、而"进度推进"失败这个**矛盾**反推出来的。

## 亮点 4 · 班级群聊实时化：2~3 秒送达，无需刷新

**一句话**：用 SSE 做增量推送，同班同学发言后其他人不用刷新就能看到。

- **背景**：群聊原本只有"手动刷新"按钮，班级场景下体验割裂。
- **做法**：后端 `POST /api/group/messages/stream`——async 生成器每 2 秒查一次**增量**（`created_at > 游标`），有则推 `data` 帧、无则推注释行保活；**300 秒后自动结束**由前端重连（避免长连接长期占用）；关闭反代缓冲（`X-Accel-Buffering: no`）。前端按消息 id 去重、指数退避重连（最多 3 次）、切页签与卸载时主动断开。
- **实测数据**：服务端 **5/5**（流建立 / 发消息 2~8 秒内自动推送 / 无效身份拒绝）+ 浏览器端 **3/3**（群聊页打开后，另一方发言，页面无需任何操作即出现新消息）。

## 亮点 5 · 首屏加载优化 59%：先定位真因，再动手

**一句话**：没有按"拆包"这个常见套路走，而是先测出真凶——`index.html` 里 4 个同步脚本。

- **背景**：首屏可用 3~4 秒，开场动画只是把等待盖住了。
- **诊断**：路由**其实已经分包**（每个页面都是独立 chunk），真正的瓶颈是 HTML 里 4 个**同步 `<script>`**（图表库 + 代码编辑器及相关 mode，约 396KB）**阻塞首屏**。
- **做法**：新建 `lib/lazyLibs.js` 按需注入（同一资源只加载一次、并发调用共享 Promise、失败清缓存可重试）；调用点改为 `await` 并带**降级**（拿不到库就退化为纯文本域，不让页面白屏）；保留体积小且被高频文本组件使用的代码高亮库。
- **实测数据**：

| 指标 | 优化前 | 优化后 | 变化 |
|---|---|---|---|
| **首页可用时间** | 3990ms | **1618ms** | **−59%** |
| DOMContentLoaded | 3736ms | 612ms | −84% |
| 传输总量 | 902KB | 506KB | −44% |
| 重库体积 | 521KB | 125KB | −76% |

- **附带发现**：图表库在当前版本其实**已无页面使用**（旧学情看板组件已退役），因此它不进首屏是纯收益。

## 亮点 6 · 让 AI 看见"纸面上"的信息：涂改与空白

**一句话**：给转录加上 `{涂改}` / `{空白}` 标记，让判分能识别"跳步"和"涂改"这类纸面问题。

- **背景**：纯文字转录会丢掉纸面信息——学生划掉了什么、哪题空着没写，判分模型看不到。
- **做法**：转录提示词要求标注，并把格式**收紧到只允许两种标记**（"涂改/划掉/涂黑一律写 `{涂改}`，不要自创写法"）。
- **实测数据**：用一张带涂改块的样本图验证——第一次模型输出了自造的 `{涂黑}`（格式不统一，下游无法稳定匹配），收紧措辞后复验，在**正确位置**稳定输出 `{涂改}`；跳步样本上，判分准确识别"只给答案不给过程"并扣分（60/70）。
- **为什么有价值**：为将来做"书写规范分"（按标记统计涂改处数、空白题数）预留了**数据接口**——链路已经通了。

## 亮点 7 · 公式渲染三级降级：页面上绝不出现裸 `$`

**一句话**：AI 输出的公式有三种形态，用三级降级保证**任何情况下**学生看到的都不是源码。

- **背景**：模型输出可能带 LaTeX、可能格式不合法；一旦解析失败，页面上会直接漏出 `$...$` 源码，体验崩塌。
- **做法**：结构化字段走 MathText（katex）→ 解析失败退 `latexToPlain`（转可读纯文本）→ 仍失败按纯文本展示；流式过程中先纯文本、**结束后统一渲染公式**（避免半截公式闪烁）；JSON 解析先试"修复版"再退回原文。
- **体现什么**：这类"失败路径设计"是工程完整性的直接体现——评委看的是**边界处理**，不是 happy path。

---

## 亮点 8 · 模型按调用位配置，且永不因缺 Key 而瘫

**一句话**：识别、讲解、判分各用各的模型与 Key，可分别调成本与质量；没配 Key 也能跑（内置 Mock）。

- **做法**：三个调用位（识别/讲解/判分）各有独立环境变量，默认各配最合适的模型；任一调用失败可降级到备用模型；未配置 Key 时走内置 Mock，**功能链路不中断**（便于演示与开发）。
- **为什么是设计亮点**：教学场景里"成本敏感"与"质量敏感"同时存在——老师批改可以用便宜模型、学生讲解要用强推理模型。把模型解耦成调用位，是**可运营**的设计，不是 demo 级实现。
